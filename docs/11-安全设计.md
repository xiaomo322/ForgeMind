# ForgeMind 安全设计

**版本：V0.1**  
**状态：核心已确定**

## 1. 核心原则

安全优先于效率。LLM 不是安全边界，Agent 的判断必须由 Runtime 在执行层进行最终兜底。

## 2. 双层防线

```text
第一层：Agent Policy
Agent 根据任务、权限和风险判断是否应该调用

第二层：Runtime Enforcement
Runtime 在 Tool 执行前再次校验并拦截
```

即使 Agent 判断错误、上下文被污染或受到提示攻击，Runtime 仍应阻止未授权操作。

## 3. 风险判断因素

- 操作本身；
- 操作对象；
- 操作范围；
- 数据重要程度；
- 是否可恢复。

## 4. 高风险操作示例

- 删除数据库或数据；
- 生产数据库操作；
- 删除大量文件；
- 修改敏感文件；
- 危险 Shell 命令；
- 生产环境部署。

这些操作必须经过 Runtime 拦截，并在需要时等待用户明确确认。

## 5. 安全失败原则

权限不足、参数不完整、风险无法判断或目标范围不清楚时，默认拒绝执行或暂停确认，不以效率为理由放宽限制。

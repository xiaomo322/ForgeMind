# ForgeMind 数据结构设计

**版本：V0.1**  
**状态：概念模型已确定，Schema 待定**

## 1. State 的作用

State 不是普通日志，而是 Agent Loop 的上下文载体，使 Agent 能在下一轮循环中知道当前目标、进度、已执行事实和验证结果。

## 2. State 概念模型

```text
ForgeMindState
├── task
├── progress
├── context
├── findings
├── actions
├── verification
└── permissions
```

## 3. 字段含义

| 区域 | 记录内容 |
|---|---|
| `task` | 用户问题、任务目标和完成条件 |
| `progress` | 当前阶段和任务进度 |
| `context` | 已查看文件、相关符号等任务上下文 |
| `findings` | 候选问题、怀疑问题和已确认问题 |
| `actions` | 已经发起和执行过的操作 |
| `verification` | 程序、已有测试和新测试结果 |
| `permissions` | 权限范围和用户确认情况 |

## 4. 事实来源原则

涉及客观执行事实的 State，应尽可能由 Runtime 根据 Tool 的实际结果更新，而不是由 Agent 自己声称。

```text
Agent 产生 read_file Action
  ↓
Tool 成功读取
  ↓
Observation 返回
  ↓
Runtime 更新 examined_files
```

如果 Tool 执行失败，不得把目标文件记录为已成功读取。

## 5. Action 与 Observation

Action 至少需要能够表达：

```text
action_id
action_type
tool_name
arguments
target
reason
```

Observation 至少需要表达执行状态、结果内容或摘要、错误信息和相关元数据。

完整字段类型、枚举值和校验规则将在后续 Schema 设计阶段确定。

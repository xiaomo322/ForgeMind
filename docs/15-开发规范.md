# ForgeMind 开发规范

**版本：V0.1**  
**状态：初步确定**

## 1. 范围纪律

实现时只处理已确认需求，不因“看起来有用”而提前加入 RAG、Memory、Multi-Agent 或复杂业务能力。

## 2. 设计同步

模块设计先记录到对应正式文档，经确认后再进入代码实现；实现结果和重要变更记录到项目开发日志。

## 3. Agent 系统边界

- Agent 做决策；
- Runtime 做结构、权限和安全校验；
- Tool 做具体执行；
- 事实 State 来自实际执行结果；
- Tool 不接受模糊自然语言指令替代结构化参数。

## 4. 验证要求

代码修改后应进行代码检查、程序运行和相关测试，并记录必要的新测试、未验证部分及风险。

## 5. 安全要求

无法确认权限、范围或可恢复性时，采用保守处理并请求用户确认。

# ForgeMind 开发规范

**版本：V0.1**  
**状态：初步确定**

## 1. 范围纪律

实现时只处理已确认需求，不因“看起来有用”而提前加入 RAG、Memory、Multi-Agent 或复杂业务能力。

## 2. 设计同步

每次只设计当前实现切片需要的契约，讲清后尽快进入小段代码和测试。正式文档记录已确认决定、实现结果和验证证据，不提前连续扩写大量未来设计。

## 3. Agent 系统边界

- Agent 做决策；
- Runtime 做结构、权限和安全校验；
- Tool 做具体执行；
- 事实 State 来自实际执行结果；
- Tool 不接受模糊自然语言指令替代结构化参数。

## 4. 验证要求

代码修改后应进行代码检查、程序运行和相关测试，并记录必要的新测试、未验证部分及风险。

## 5. 安全要求

无法确认权限、范围或可恢复性时，采用保守处理并请求用户确认。

## 6. 教学与协作方式

每个小切片采用“理解 30% → 用户实现 30% → AI 辅助 20% → 测试、Debug、解释 20%”的重心分配。

- AI 先解释核心原理、数据流和代码边界；
- 用户亲手完成一段边界明确的核心函数或关键分支；
- AI 负责脚手架、测试、提示、审查及非核心补充；
- 双方依据真实测试输出定位问题并解释修复原因；
- 完成连贯模块时，AI 提供带中文步骤注释的模块级测试骨架，由用户亲手编写关键测试代码；普通小切片测试仍由 AI 负责；
- 用户尚未理解时先教学，不要求依靠未讲过的知识猜答案；
- 详细执行规则以项目根目录 `AGENTS.md` 为准。

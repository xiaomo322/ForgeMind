# ForgeMind 服务器部署

## 1. 部署结构

生产镜像分为两个阶段：

1. Node 阶段把 `frontend/` 编译成浏览器可直接加载的静态文件；
2. Python 阶段安装 ForgeMind 后端，并把前端构建产物交给 FastAPI 托管。

浏览器只访问同一个 ForgeMind 服务：普通 HTTP 请求用于上传项目、创建任务和提交用户决定，SSE 长连接用于持续接收 Agent 的执行事件。模型 API Key 只存在于服务器环境中，不会发送到浏览器。

运行数据写入 `/data`：

- `/data/state.db` 保存任务、Action、Observation 和等待状态；
- `/data/workspaces/` 保存用户上传并经过校验的 Python 工作区。

`compose.yaml` 把 `/data` 绑定到 Docker 命名卷，所以重新创建容器后任务数据仍然存在。
容器以非 root 用户运行，根文件系统只读，只开放可持久化的 `/data` 和受限大小的 `/tmp`，并删除额外 Linux capabilities、禁止重新提升权限。

## 2. 首次部署

服务器需要安装 Docker Engine 和 Docker Compose 插件。进入项目根目录后执行：

```bash
cp .env.example .env
```

编辑 `.env`，只填写服务器真实使用的密钥：

```dotenv
DEEPSEEK_API_KEY=你的真实密钥
```

不要把 `.env` 提交到 Git，也不要把 API Key 写进前端代码、Dockerfile 或 `config/model.toml`。

构建并启动：

```bash
docker compose up --build -d
```

检查服务：

```bash
curl http://127.0.0.1:8000/health
docker compose logs -f forgemind
```

健康检查应返回 `200`。在服务器本机访问 `http://127.0.0.1:8000` 可以看到 ForgeMind 工作台；远程浏览器应访问下一节配置的 HTTPS 反向代理地址。

## 3. 为什么默认只监听本机

`compose.yaml` 使用 `127.0.0.1:8000:8000`。这表示外部网络不能绕过服务器入口直接访问 ForgeMind。需要远程访问时，应在前面配置 Nginx、Caddy 或云负载均衡，并添加 HTTPS 与身份认证。

Nginx 的关键代理边界示例：

```nginx
client_max_body_size 6m;

location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 3600s;
}
```

`client_max_body_size` 在请求到达 FastAPI 前限制上传体积；`proxy_buffering off` 防止 Nginx 把 SSE 事件积累到流结束才交给浏览器。身份认证应在这个入口或上游网关配置。

ForgeMind 会在容器内运行上传项目的 Python 命令。当前版本适合个人、可信用户或受控内网部署。它还不是允许陌生用户执行任意代码的公共多租户平台。若要公开提供服务，需要增加独立任务沙箱、资源限额、网络隔离、用户认证和审计。

## 4. 日常运维

更新代码后重新构建：

```bash
docker compose up --build -d
```

停止服务但保留数据：

```bash
docker compose down
```

备份命名卷中的 SQLite 与上传工作区：

```powershell
docker run --rm -v forgemind-data:/data:ro -v "${PWD}:/backup" alpine tar -czf /backup/forgemind-data.tgz -C /data .
```

恢复前先停止 ForgeMind，再把备份解压到同一个命名卷。备份时停止写入可以保证 `state.db` 与工作区内容属于同一时刻。

只有明确要删除全部 ForgeMind 持久数据时，才使用 `docker compose down -v`。

## 5. 前端操作流程

1. 选择一个或多个扁平目录中的 `.py` 文件并上传；
2. 输入任务目标并创建 Agent 任务；
3. 页面通过 SSE 展示读取、检索、修改和测试等真实执行事件；
4. Agent 提问时填写答案，遇到修改或命令权限时明确批准或拒绝；
5. 一批最多自动执行 20 步；达到上限后检查左侧记录，再点击“继续运行”；
6. 任务完成后停止；模型输出错误或连接失败时检查记录并点击“重试连接”。

上传接口限制为 1–20 个 UTF-8 Python 文件，单文件不超过 1 MiB，总大小不超过 5 MiB。文件名必须是普通文件名，不能包含目录分隔符。限制在服务端执行，不能通过修改浏览器页面绕过。

`run_tests` 和 `run_command` 启动的子进程使用环境变量允许列表，只获得 Python 运行所需的系统变量和独立临时目录，不会继承服务器进程中的 `DEEPSEEK_API_KEY`。同一任务同一时刻只允许一条 SSE 执行流，避免多个浏览器标签页同时驱动同一个 Agent。

# ForgeMind 持久任务、工作区 ZIP 导入导出设计

## 目标

让单机 ForgeMind 的任务和项目在服务重启、页面刷新及创建新任务后仍然可找回。用户可以上传一个 ZIP 作为新的独立工作区，也可以把任务绑定的当前工作区整体下载为 ZIP。

## 已确认的产品行为

- 每次 ZIP 上传创建新的独立工作区，不合并或覆盖已有工作区。
- 每个任务继续持久绑定一个服务端工作区；任务列表从 SQLite 恢复，不依赖浏览器本地存储。
- 页面提供历史任务入口，选择任务后使用现有任务快照接口恢复对话、执行记录和项目文件。
- 项目文件提供整个工作区 ZIP 下载，不增加逐文件下载。
- 原有多文件 `.py` 上传继续可用，新增 ZIP 上传作为另一种创建工作区的方式。

## 后端设计

### ZIP 导入

`POST /workspaces/archive` 接收一个 `.zip` 文件并返回现有 `UploadedWorkspace` 结构。存储层先检查全部 ZIP 条目，再写入临时目录，最后原子重命名为正式工作区。

安全边界：

- 拒绝绝对路径、`..` 路径穿越、Windows 盘符和反斜杠混淆路径；
- 拒绝符号链接、加密条目、重复规范化路径和空压缩包；
- 跳过目录条目，保留安全的嵌套目录结构；
- 限制压缩包体积、解压后文件数、单文件体积和总解压体积，防止 ZIP 炸弹；
- 不把服务器绝对路径返回给浏览器。

### ZIP 导出

`GET /tasks/{task_id}/workspace.zip` 通过任务的权威 `project_root` 找到工作区并动态生成 ZIP。只包含活动工作区中的普通文件，不包含暂存附件或工作区外内容。响应使用附件下载头，并用任务编号生成稳定文件名。

### 历史任务

`GET /tasks?limit=50` 返回按创建顺序倒排的任务摘要，包括任务编号、用户原始目标、当前状态、状态修订号和公开工作区编号。SQLite `tasks` 表的插入顺序作为当前单用户 MVP 的稳定排序依据；已有数据库无需迁移。

## 前端设计

- 顶部工具栏增加“历史任务”按钮，打开独立抽屉；抽屉显示任务目标、状态和编号，点击后切换 URL 并恢复该任务。
- 新建任务页也能打开历史任务，因此离开某个任务后仍能找回。
- 新建工作区表单接受多个 `.py` 文件或一个 `.zip` 文件；ZIP 与普通文件不能混合提交。
- 项目文件抽屉顶部增加“下载工作区 ZIP”按钮，浏览器直接访问任务下载接口。
- 所有错误继续显示为非技术化中文提示，保持现有深色 Codex 风格和移动端抽屉布局。

## 验证

- 存储层测试覆盖 ZIP 正常解压、嵌套目录、路径穿越、符号链接、重复路径和容量限制。
- API 测试覆盖 ZIP 上传、任务历史顺序、重启后恢复和 ZIP 下载内容。
- 前端测试覆盖 ZIP 创建工作区、历史任务打开和下载入口。
- 最后运行完整 Python 测试、前端单元测试、生产构建，并在真实浏览器中验证上传、创建、切换、刷新和下载流程。
